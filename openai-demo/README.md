# Локальный помощник закупок

Все настройки подключения читаются только из корневого .env. Изменения применяются со следующего запроса без перезапуска PHP. Не публикуйте ключ и не добавляйте .env в Git.

## Текущая настройка: GigaChat для физического лица
```dotenv
API_KEY=ваш_Authorization_key
API_MODEL=GigaChat-Pro
API_URL=https://gigachat.devices.sberbank.ru/api/v1/chat/completions
API_AUTH=oauth_basic
API_AUTH_URL=https://ngw.devices.sberbank.ru:9443/api/v2/oauth
API_SCOPE=GIGACHAT_API_PERS
API_PROTOCOL=chat
API_FORMAT=prompt
API_TOKEN_PARAM=max_tokens
API_MAX_TOKENS=4096
```
API_KEY — готовый Authorization key из кабинета API, без префикса Basic. Это не отдельный Client Secret. Токен доступа клиент получает автоматически перед анализом. Для корпоративного аккаунта задайте scope своего тарифа.

## Смена сервиса
Достаточно изменить .env, если сервис поддерживает один из реализованных протоколов:
- API_URL: полный HTTPS-адрес метода, включая /chat/completions или /responses.
- API_AUTH: bearer для обычного ключа; oauth_basic для обмена Basic-ключа на access_token по указанному API_AUTH_URL и API_SCOPE.
- API_PROTOCOL: chat (Chat Completions) или responses.
- API_FORMAT: prompt (JSON по инструкции, для широкой совместимости), json_object или json_schema (только если поддерживается выбранной моделью).
- API_TOKEN_PARAM: max_tokens, max_completion_tokens или max_output_tokens по документации сервиса.
- API_MODEL и API_KEY: идентификатор модели и ключ именно выбранного сервиса.
- API_MAX_TOKENS: ограничение выходных токенов, от 1 до 32768.
- API_CA_BUNDLE: необязательный абсолютный путь к PEM-файлу официальных доверенных сертификатов.

По одному ключу нельзя надёжно определить провайдера и способ авторизации. Сервисы с другими протоколами потребуют нового адаптера. Не смешивайте ключ одного сервиса с адресом другого.

В режиме prompt модель может ошибиться в JSON. Приложение проверяет структуру и типы полей, а не выдаёт некорректный ответ за результат. При ошибке формата выполняется не более одного дополнительного запроса для исправления JSON, с расходом квоты. Если исправление не удалось, показывается исходный ответ с предупреждением, без таблицы условий. Исправленные значения требуют сверки с письмом; оригинал ответа доступен на странице.

## Запуск
Из корня проекта:
```powershell
powershell -ExecutionPolicy Bypass -File .\openai-demo\start.ps1
```
Откройте http://127.0.0.1:8088. Если сервер уже работает, второй запуск не нужен. Остановка запущенного в терминале сервера — Ctrl+C.

PHP 8.2+, cURL, OpenSSL, mbstring и iconv. Публичный каталог — только openai-demo/public. Закрытые настройки и код находятся вне него. Проверка HTTPS всегда включена; в Windows используются также системные доверенные сертификаты.

Приложение готовит запросы закупки, отправляет отдельные письма выбранным поставщикам, автоматически собирает ответы, анализирует все товары и строит предварительный топ до пяти поставщиков. Интеграция в Битрикс24 пока не выполнена. Квоты и оплата зависят от выбранного ИИ-сервиса.

## Формат результата
Ответ содержит summary, items, common_attributes и questions.
items — массив всех обнаруженных товаров или услуг. Каждая позиция имеет name и attributes.
attributes и common_attributes содержат объекты с label (произвольное название), value (значение) и quote (цитата или null).
Название и количество характеристик не ограничены перечнем в PHP: можно вернуть комплектацию, обучение, оговорки, документы и другие сведения.
Общие условия не подставляются автоматически во все товары. Приложение не вычисляет цены и не восстанавливает отсутствующие факты.
Разбор структуры не гарантирует полноту и правильность извлечения моделью — результат следует сверить с письмом.
Проверка обработчика: .runtime/php/php.exe openai-demo/tests/parse-offer.php

## Новый сценарий закупки

В правом верхнем углу находится «Завершить работу». Кнопка останавливает этот PHP-сайт на 8088 и его фоновый обработчик почты. Она доступна и до входа в почту. Запрос защищён CSRF и выполняется только для локального встроенного PHP-сервера; посторонние процессы не завершаются. Страница показывает подтверждение после закрытия порта. Запросы закупки и анализ остаются сохранёнными. Для нового запуска используйте `start.ps1`.

Остановку выполняет отдельный скрытый помощник `stop.ps1`, чтобы сервер успел вернуть ответ браузеру. Результат остановки — `.runtime/shutdown-result.json`, ошибки запуска — `.runtime/shutdown.err.log`. Проверка ограничений без остановки: `.runtime/php/php.exe openai-demo/tests/shutdown.php`.

1. Войти в почту помощника на сайте.
2. Тезисно описать закупку и нажать «Сформировать письмо». ИИ создаёт тему и текст; сотрудник может их исправить.
3. Выбрать поставщиков флажками и отправить. Каждому уходит отдельное письмо; другие адресаты ему не видны. В тему добавляется уникальный маркер [ЗКП-номер]. Само формирование черновика ничего не отправляет.
4. После поступления ответов помощник сохраняет оригиналы, анализирует все товары и строит топ до пяти поставщиков. Если подходящих предложений меньше пяти, список короче. Отказы и письма без предложения не должны попадать в топ.
5. «Обновить ответы и анализ» запускает внеочередную проверку. При отсутствии новых писем ИИ не вызывается, если нет незавершённого анализа предыдущих писем. Ошибки ИИ повторяются по расписанию через час либо кнопкой «Повторить анализ с ошибками».

Список адресов — `openai-demo/suppliers.txt`, одна почта в строке. Уже добавлены andryrodi8@gmail.com и r0dionov.andrew@yandex.ru. Пустые строки и строки с # игнорируются, дубли удаляются. До 20 поставщиков. Изменения видны при обновлении страницы. Уже отправленные запросы сохраняют свой список адресатов.

Структура генерируемого письма: приветствие, цель закупки, перечень товаров и требований, известные условия поставки, перечень ожидаемых условий КП (цены, НДС, доставка, оплата, гарантия, документы, срок действия), известный срок ответа и контакты, подпись. Основа структуры: [образец запроса КП DocWatch](https://www.docwatch.ru/blog/zapros-kommercheskogo-predlozheniya). Реквизиты и неизвестные условия модель не должна придумывать.

### Отбор входящих

Просматриваются новые письма INBOX после отправки запроса, а не последние двадцать писем. Письмо подходит, если его отправитель совпадает с адресом поставщика, которому отправлен запрос, либо оно связано с запросом через In-Reply-To/References, либо содержит Re:/Ответ: и совпадающую тему с номером закупки. Одного слова Re: недостаточно. Автоответы и массовые рассылки по служебным заголовкам исключаются.

Заголовки ответа имеют приоритет. Если найден только адрес, а этот поставщик участвует в нескольких запросах, письмо относится к последнему запросу и помечается предупреждением о неоднозначности. При ответе с другого адреса по заголовкам цепочки сохраняется связь с исходным поставщиком. Эта эвристика требует проверки сотрудником. Почтовые заголовки сами по себе не удостоверяют личность отправителя.

UID и UIDVALIDITY предотвращают повторную загрузку; при смене папки дополнительно проверяются Message-ID и текст. За проход проверяются до 60 новых писем, оставшиеся загружаются следующими проходами. Чтение письма не отправляет ответ поставщику. HTML преобразуется в текст без внешних картинок. Вложения перечисляются, но не анализируются. Лимиты: письмо до 5 МБ, текст анализа до 24 КБ. Неподдерживаемое письмо показывается с причиной.

### Суммаризация и топ

Изображения (в том числе PNG/JPEG и логотипы подписи) пропускаются до декодирования содержимого MIME: они не передаются ИИ, не сохраняются отдельными файлами и не выводятся в предупреждениях. Список уже загруженных вложений также фильтруется при показе. Документы других типов по-прежнему перечисляются как не проанализированные.

Топ использует компактный ответ модели: supplier_id, reason, fact_ids, risks. Сервер заранее собирает каталог фактов с цитатами из текста письма; модель выбирает их идентификаторы и порядок поставщиков. PHP подставляет исходные значения, адреса и цитаты без повторного переписывания их моделью. Факт другого поставщика, выдуманный идентификатор или неподтверждённая цитата не принимаются. Если в прежнем анализе цитат нет, доступны явно помеченные фрагменты исходного письма. Полный анализ всех товаров остаётся доступным отдельно.

Каждое письмо анализируется один раз; успешный результат сохраняется вместе с оригиналом. Полный анализ содержит массив всех товаров и произвольные характеристики. После изменения набора проанализированных писем ИИ пересобирает топ по всей доступной переписке этого запроса: соответствие требованиям, сопоставимая полная стоимость, доставка, оплата, гарантия. Приоритеты пока задаются инструкцией модели; это предварительная рекомендация, а не детерминированная балльная оценка.

Факты в топе привязаны к конкретному письму и поставщику. Сервер проверяет адреса, отсутствие дублей, максимум пять поставщиков и наличие каждой цитаты в исходном тексте. Эти проверки не доказывают правильность интерпретации: цены разных комплектаций, валют, налогов и количеств нельзя автоматически считать сопоставимыми. Ограничения и риски выводятся рядом с топом. Исходное письмо открывается отдельно; все полученные письма и их анализ доступны ниже.

Если модель недоступна или формат ответа неверен, письмо и прежний анализ сохраняются, выводится ошибка. При HTTP 500/502/503/504 допускается один повтор исходного запроса; при ошибке JSON — один запрос исправления формата (до трёх попыток генерации). Отказы доступа, лимита и неоднозначные сетевые обрывы автоматически не повторяются. Цитата, которой нет в письме, блокирует публикацию нового топа. Большая переписка свыше 180 КБ входных данных сравнения требует разделить закупку на отдельные запросы; данные молча не обрезаются.

## Почта и фоновая проверка

Адрес и пароль вводятся на сайте. В .env остаются серверные параметры:
```dotenv
MAIL_IMAP_HOST=mail.olimp5.ru
MAIL_IMAP_PORT=993
MAIL_SMTP_HOST=mail.olimp5.ru
MAIL_SMTP_PORT=465
MAIL_SMTP_SECURITY=ssl
MAIL_FOLDER=INBOX
MAIL_DOMAIN=citology.ru
MAIL_SENDER_NAME=Отдел закупок
```
Для входа используется полный адрес. IMAP и SMTP используют LOGIN поверх проверенного TLS. MAIL_CA_BUNDLE задаёт отдельный PEM-файл; по умолчанию используется curl.cainfo. Пароль не берётся из кода или .env.

`start.ps1` запускает PHP-сайт и один скрытый фоновый процесс `worker.php --loop`. Обработчик проверяет срок задач каждые 15 секунд: почту раз в 3600 секунд, очередь новых писем — последовательно, по одной задаче за проход. Закрытие вкладки не останавливает проверку. Компьютер и процесс PHP должны работать; при выключенном компьютере проверок нет. После перезапуска просроченные задачи подхватываются автоматически. При обычном завершении start.ps1 запущенный им обработчик также завершается. Для сервера можно вызывать `php openai-demo/worker.php` раз в минуту штатным планировщиком: без --loop это один проход.

После входа данные почты сохраняются для фонового доступа в `.runtime/procurement/<аккаунт>/auth.json` с AES-256-GCM. Локальный ключ находится отдельно в `.runtime/procurement/key.bin`; это защита хранения, а не защита от владельца компьютера с доступом ко всем файлам. Нельзя публиковать или передавать .runtime целиком. Выход на сайте удаляет зашифрованный пароль и прекращает последующие фоновые операции; уже выполняющийся запрос может завершиться. Веб-сессия истекает через 30 минут бездействия, фоновое подключение продолжает работать до явного выхода. Для возврата к интерфейсу нужен повторный вход.

Запросы закупки, письма и анализ хранятся в `.runtime/procurement/<аккаунт>/state.json`, вне public. Одновременные запросы браузера и обработчика защищены блокировкой. Журнал SMTP в `.runtime/mail` предотвращает повторную отправку при повторном нажатии или обрыве ответа сайта. Неизвестный результат SMTP не повторяется автоматически. Принятие SMTP не гарантирует фактическую доставку. Копирование писем в папку «Отправленные» сервиса пока не реализовано.

Для IMAP используется cURL, для SMTP — PHPMailer 7.1.1. SMTP-проверка из старого интерфейса остаётся доступной только на уровне API. Старый отдельный анализ текста сохранён в сворачиваемом блоке. Публичные маршруты перечислены в router.php; конфигурация, список адресов, журнал и ключ не доступны по HTTP.

## Проверки

Без реальной отправки и обращений к ИИ:
```powershell
.runtime/php/php.exe openai-demo/tests/parse-offer.php
.runtime/php/php.exe openai-demo/tests/mail.php
.runtime/php/php.exe openai-demo/tests/api-retry.php
.runtime/php/php.exe openai-demo/tests/procurement.php
node --check openai-demo/public/app.js
```
Проверяются MIME, адресаты, повторная отправка, связь с закупкой по адресам/теме/References, исключение чужого Re:, отсутствие повторного анализа и вызова ИИ при пустой очереди, сохранение всех товаров, сбои и ручной повтор, цитаты и изоляция аккаунтов. Тесты создают только отдельные временные данные.
