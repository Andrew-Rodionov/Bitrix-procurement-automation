# Локальный помощник закупок

Все настройки подключения читаются только из корневого .env. Изменения применяются со следующего запроса без перезапуска PHP. Не публикуйте ключ и не добавляйте .env в Git.

## Текущая настройка: GigaChat для физического лица
```dotenv
API_KEY=ваш_Authorization_key
API_MODEL=GigaChat-Pro
API_URL=https://gigachat.devices.sberbank.ru/api/v1/chat/completions
API_AUTH=oauth_basic
API_AUTH_URL=https://ngw.devices.sberbank.ru:9443/api/v2/oauth
API_SCOPE=GIGACHAT_API_PERS
API_PROTOCOL=chat
API_FORMAT=prompt
API_TOKEN_PARAM=max_tokens
API_MAX_TOKENS=4096
```
API_KEY — готовый Authorization key из кабинета API, без префикса Basic. Это не отдельный Client Secret. Токен доступа клиент получает автоматически перед анализом. Для корпоративного аккаунта задайте scope своего тарифа.

## Смена сервиса
Достаточно изменить .env, если сервис поддерживает один из реализованных протоколов:
- API_URL: полный HTTPS-адрес метода, включая /chat/completions или /responses.
- API_AUTH: bearer для обычного ключа; oauth_basic для обмена Basic-ключа на access_token по указанному API_AUTH_URL и API_SCOPE.
- API_PROTOCOL: chat (Chat Completions) или responses.
- API_FORMAT: prompt (JSON по инструкции, для широкой совместимости), json_object или json_schema (только если поддерживается выбранной моделью).
- API_TOKEN_PARAM: max_tokens, max_completion_tokens или max_output_tokens по документации сервиса.
- API_MODEL и API_KEY: идентификатор модели и ключ именно выбранного сервиса.
- API_MAX_TOKENS: ограничение выходных токенов, от 1 до 32768.
- API_CA_BUNDLE: необязательный абсолютный путь к PEM-файлу официальных доверенных сертификатов.

По одному ключу нельзя надёжно определить провайдера и способ авторизации. Сервисы с другими протоколами потребуют нового адаптера. Не смешивайте ключ одного сервиса с адресом другого.

В режиме prompt модель может ошибиться в JSON. Приложение проверяет структуру и типы полей, а не выдаёт некорректный ответ за результат. При ошибке формата выполняется не более одного дополнительного запроса для исправления JSON, с расходом квоты. Если исправление не удалось, показывается исходный ответ с предупреждением, без таблицы условий. Исправленные значения требуют сверки с письмом; оригинал ответа доступен на странице.

## Запуск
Из корня проекта:
```powershell
powershell -ExecutionPolicy Bypass -File .\openai-demo\start.ps1
```
Откройте http://127.0.0.1:8088. Если сервер уже работает, второй запуск не нужен. Остановка запущенного в терминале сервера — Ctrl+C.

PHP 8.2+ и cURL. Публичный каталог — только openai-demo/public. Закрытые настройки и код находятся вне него. Проверка HTTPS всегда включена; в Windows используются также системные доверенные сертификаты.

Пример анализирует письмо, но не отправляет сообщения поставщикам и пока не интегрирован в Битрикс24. Квоты, оплата и правила обработки данных зависят от выбранного сервиса.

## Формат результата
Ответ содержит summary, items, common_attributes и questions.
items — массив всех обнаруженных товаров или услуг. Каждая позиция имеет name и attributes.
attributes и common_attributes содержат объекты с label (произвольное название), value (значение) и quote (цитата или null).
Название и количество характеристик не ограничены перечнем в PHP: можно вернуть комплектацию, обучение, оговорки, документы и другие сведения.
Общие условия не подставляются автоматически во все товары. Приложение не вычисляет цены и не восстанавливает отсутствующие факты.
Разбор структуры не гарантирует полноту и правильность извлечения моделью — результат следует сверить с письмом.
Проверка обработчика: .runtime/php/php.exe openai-demo/tests/parse-offer.php

## Почта — ручная обработка входящих

Подключается один ящик помощника. Адреса поставщиков вводятся в форме отправки (до 20, через запятую, точку с запятой, пробел или новую строку). Каждому отправляется отдельное текстовое письмо; другие получатели ему не видны. Нажатие «Отправить письма» непосредственно отправляет введённый сотрудником текст.

Для ящика @citology.ru используется Kerio Connect на mail.olimp5.ru. Адрес и пароль вводятся в форме «Войти в почту» на странице. В .env остаются только серверные параметры:
```dotenv
MAIL_IMAP_HOST=mail.olimp5.ru
MAIL_IMAP_PORT=993
MAIL_SMTP_HOST=mail.olimp5.ru
MAIL_SMTP_PORT=465
MAIL_SMTP_SECURITY=ssl
MAIL_FOLDER=INBOX
MAIL_DOMAIN=citology.ru
MAIL_SENDER_NAME=Отдел закупок
```
Для авторизации используется полный адрес ящика. MAIL_CA_BUNDLE — отдельный PEM-файл доверенных сертификатов почты; по умолчанию используется curl.cainfo из PHP. Проверка TLS включена. Изменения .env не требуют перезапуска.

«Проверить почту» загружает последние 20 писем INBOX. Нажатие темы загружает текст в существующий редактор. Затем сотрудник проверяет текст и нажимает «Разобрать предложение». Проверка и выбор письма не обращаются к ИИ. HTML преобразуется в текст без загрузки внешних картинок. Вложения перечисляются, но не анализируются. Письма больше 5 МБ не загружаются. Лимит текста анализа остаётся 24 КБ.

Отправка ведёт локальный закрытый журнал .runtime/mail. Повтор одного запроса показывает сохранённый результат и не отправляет письма снова. При обрыве SMTP результат может быть неизвестен: не повторяйте такую отправку без проверки. «Новое письмо» создаёт новый идентификатор отправки. Принятие SMTP-сервером не гарантирует доставки в ящик получателя.
Копирование отправленных писем в папку почтового сервиса пока не реализовано; введённый текст и результат отправки сохраняются локально. Входящие перечитываются с сервера, результаты ИИ пока не привязаны к заявкам и не сохраняются как переписка.

Для чтения используется IMAP через cURL, для отправки — PHPMailer 7.1.1 (официальный исходный код и лицензия в lib/PHPMailer). Установка через Composer не нужна. PHP должен поддерживать протокол imaps в cURL, iconv и OpenSSL.

Тесты без реальной рассылки:
```powershell
.runtime/php/php.exe openai-demo/tests/mail.php
```

MAIL_DOMAIN ограничивает только адрес ящика помощника. Получатели могут быть на любых доменах. При смене провайдера измените параметры в .env. Сервер должен разрешать вход полным адресом ящика. Способ входа (обычный пароль, пароль приложения или иные ограничения) уточняется у администратора. Доступность серверов и TLS проверены без авторизации; доступ к конкретному ящику требует правильных учётных данных.

Вход с сайта: откройте страницу, введите полный адрес @citology.ru, пароль. Программа проверит вход по IMAP и только после успеха сохранит данные в закрытой серверной сессии .runtime/sessions. Учётные данные не берутся из .env и не возвращаются в JSON. Кнопка выхода очищает их, после 30 минут бездействия понадобится новый вход. SMTP проверяется при отправке. Настройка для localhost; при публикации сайта требуется HTTPS.

IMAP-авторизация явно использует SASL LOGIN поверх проверенного TLS, поддерживаемый Kerio. Ошибка cURL 67 означает отказ авторизации; сама по себе она не доказывает неверный пароль. Возможны ограничения доступа к IMAP, дополнительная аутентификация или ограничения учётной записи. Подробную причину проверяет администратор в журнале Kerio.
Кнопка «Проверить SMTP без отправки» проверяет соединение и авторизацию, не отправляя письма. Явные отказы сохраняются со статусом failed и диагностикой; при неизвестном результате сохраняется unknown. Старые записи unknown без диагностики не позволяют восстановить причину.
При HTTP 500/502/503/504 исходный запрос к модели повторяется один раз с паузой 1 секунда. Ошибки доступа, квоты и сетевые обрывы не повторяются. Число запросов в интерфейсе учитывает повтор и исправление формата (до 3 попыток генерации). При ошибке отображается x-request-id провайдера, если он передан.
